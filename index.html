What's actually happening here

Transformers are the architecture behind almost every major AI system released since 2017 — GPT, Llama, Gemini, and most of what's followed all sit on some variant of the design introduced in the paper "Attention Is All You Need." The same core idea shows up outside text too, in image and audio models, protein-folding systems, even game-playing agents — but this page sticks to the text case, since it's the easiest one to watch happen step by step.

A text transformer really only does one thing: given everything typed so far, guess the single most likely next token. Write a whole paragraph, and you're just watching that guess get made over and over, with each new token fed back in as extra input for the next guess. Self-attention is the mechanism that lets each guess weigh which of the earlier words actually matter.

01Embedding — turns the prompt into numbers the model can do math on.
02Transformer Block, repeated 12× — mixes information between tokens, then refines each one on its own.
03Output Probabilities — turns the result into an actual ranked guess at the next word.

The model driving all of it is GPT-2 (small): 124 million parameters, nowhere near the largest model in use today, but architecturally close enough to GPT-4-class systems that everything below generalizes.

01

Embedding

Each token is looked up in a 50,257 × 768 table, then summed with a positional vector so the model knows word order. That sum is what enters the first transformer block.

Turning text into something a model can do math on takes four steps. First, tokenization splits the prompt into pieces — usually a whole word for common terms, and smaller subword chunks for longer or rarer ones. GPT-2 has 50,257 of these pieces in its vocabulary, each with its own numeric ID, visible above each token.

Second, every ID gets looked up in a token embedding table: a matrix of 50,257 rows by 768 columns, roughly 39 million learned numbers in total. Tokens that tend to appear in similar contexts end up near each other in this 768-dimensional space — part of what lets the model treat related words as related without being told so explicitly.

Third, since the embedding table alone has no sense of order, GPT-2 adds a positional vector for each slot in the sequence — position 0 gets one learned vector, position 1 another, and so on, entirely separate from what token happens to sit there.

Finally, the token vector and position vector for each slot are added together. That sum — not the token embedding alone — is the actual input to block 1.

That's the last thing that happens before block 1. Everything from here on is the transformer block — the same block, repeated 12 times.

02

Transformer Block

repeated 12×, each with its own weights

A block does two things to every token's vector, always in the same order: attention lets it borrow information from other tokens, and an MLP then refines it independently. GPT-2 (small) stacks 12 of these, each with its own separately learned weights — the output of one block becomes the input to the next. Drag the slider below to jump between any of the 12; everything under it describes what a single block actually does.

A search-engine analogy makes the three roles easier to hold onto. Query is the term you type into the search bar — what you're trying to find. Key is the title of each result — what a token has to offer as a match. Value is the actual page content you get back once a Query and a Key are judged a good match. The Key and Query lists above are exactly what feed into the next step.

2.2Splitting into heads & masked self-attention

Rather than run one large attention calculation, GPT-2 splits Q, K, and V into 12 smaller, independent heads of 64 dimensions each. Pick one to inspect:

1Dot product

Qᵢ · Kⱼᵀ for every pair. Faded cells look at the future and get discarded next.

2Scaling · mask

Divided by √64; future positions are blocked so the model can't peek ahead.

3Softmax

Each row sums to 1 — the model's actual attention distribution.

Splitting into heads lets different heads specialize — one might end up tracking nearby grammar, another long-range topic consistency — without either being forced to share capacity with the other. Within a single head, the three grids above are the whole calculation: dot product multiplies every token's Query against every other token's Key, producing a raw relevance score for each pair. Scaling divides those scores down (by the square root of 64, the head's dimension) to keep the numbers in a range that trains stably, and masking overwrites every score that looks at a future token with negative infinity — the model is only ever allowed to use what came before. Softmax then turns each row into an actual probability distribution summing to 1: the model's real, final answer to "how much should this token attend to each earlier token."

Once a head knows how much attention to pay to each earlier token, it uses those exact weights to take a weighted mix of the Value vectors — that's the formula worked out above. Do that for all 64 dimensions and all 12 heads, then concatenate the 12 results back into a single 768-dimensional vector per token, followed by one more linear projection. That projected vector is this block's attention contribution.

2.4MLP

Expanded, passed through a nonlinearity, then compressed back — refining each token independently of the others:

768 → 3072 GELU→ 768

Where attention moves information between tokens, the MLP works on each token entirely on its own. It expands the 768-dimensional vector to 3,072 dimensions, applies a GELU nonlinearity, then compresses it back down to 768. The four-fold expansion gives the model temporary extra room to represent more complex patterns before squeezing back down — this is also where a large share of a model's factual and pattern knowledge is thought to actually live.

2.5Residual connections, LayerNorm & Dropout

Three supporting mechanisms are what actually make a 12-block-deep stack trainable. A residual connection adds a layer's input back onto its own output rather than replacing it outright — GPT-2 does this once around attention and once around the MLP (see the diagram near the top of this section), which is what keeps gradients flowing cleanly all the way back through a deep stack. Layer Normalization rescales each token's vector to a consistent range right before attention and right before the MLP, which in practice makes training far more stable. Dropout randomly zeroes out a fraction of activations, but only during training, to stop the model over-relying on any single connection — it has zero effect on anything shown on this page, since this is inference, not training.

After 12 blocks, every token carries a representation built up from everything before it. Only the very last token's vector matters from here — it's what gets turned into an actual next-word guess.

03

Output probabilities

After 12 blocks, the final token's vector is projected onto all 50,257 vocabulary entries, turned into probabilities with softmax, then sampled using temperature, top-k, and top-p.

The last block's output for the final token is projected one more time, through a linear layer mapping its 768 dimensions onto all 50,257 vocabulary entries — one raw score, called a logit, per possible next token. A bigger logit means the model thinks that token is more likely, but a logit by itself isn't a probability yet.

Softmax converts the full set of logits into an actual probability distribution — every value between 0 and 1, all summing to exactly 1. The bars above are the highest-ranked candidates under that distribution for this exact prompt. Three settings then shape which token actually gets picked: temperature divides every logit before softmax runs — below 1 it sharpens the distribution toward the model's top pick, above 1 it flattens things out and lets less-likely tokens compete. Top-k throws away every candidate outside the k highest-probability tokens. Top-p instead keeps the smallest group of tokens whose probabilities add up to at least p, discarding the long tail.
